# 印流 MarkFlow — 产品需求文档 (PRD)

> 电商 / 小红书博主批量水印工具
> 版本：v1.0 MVP
> 最后更新：2026-08-25

## 一、项目概述

### 1.1 产品定位

**印流 MarkFlow** 是一款面向电商卖家、小红书博主、内容创作者的**批量图片水印工具**。支持一键为几十上百张图片添加自定义文字/图片水印，适配小红书、淘宝、拼多多等主流平台尺寸，解决手动逐张加水印效率低、现有工具广告多/收费贵的痛点。

### 1.2 一句话介绍

> 上传百张图，三秒全打好水印——专为电商和小红书博主打造的批量水印神器。

### 1.3 目标用户

| 用户群体 | 核心痛点 | 使用频率 |
|---------|---------|---------|
| 小红书博主 | 每次发笔记要给几十张图打水印，手动太慢 | 每周 3-5 次 |
| 淘宝/拼多多卖家 | 商品图批量加水印防盗图，SKU 多 | 每天 |
| 微商/代购 | 朋友圈图片加水印防盗图 | 每天 |
| 摄影师/设计师 | 作品图批量加版权水印 | 每周 |

### 1.4 为什么是蓝海

- 现有工具（如 iLoveIMG、水印管家）：广告多、批量限制、界面老旧
- 专业设计软件（PS）：学习成本高，批量操作繁琐
- 大厂不屑做：工具类、客单价低、但用户刚需且高频
- 小红书电商爆发，博主数量激增，防盗图需求旺盛

## 二、核心功能

### 2.1 MVP 功能（v1.0，2-4 周开发）

#### F1：批量图片上传
- 支持拖拽上传 / 点击选择文件夹
- 单次最多 200 张（MVP 限制，后续可扩展）
- 支持 JPG、PNG、WebP 格式
- 显示上传进度、总张数、总大小
- 支持删除单张、清空全部

#### F2：文字水印
- 自定义水印文字内容
- 字号调节（12-120px）
- 颜色选择（取色器 + 常用色板）
- 透明度调节（0%-100%）
- 旋转角度（-90° 到 90°）
- 描边/阴影效果（可选）

#### F3：图片水印（Logo）
- 上传自定义 Logo 图片（PNG 透明底最佳）
- 尺寸缩放（10%-200%）
- 透明度调节
- 旋转角度

#### F4：水印位置
- 九宫格快速定位（左上、中上、右上、左中、居中、右中、左下、中下、右下）
- 自定义边距（上下左右像素值）
- 平铺模式（水印重复铺满整张图，防盗图效果最好）

#### F5：实时预览
- 左侧原图，右侧带水印预览
- 实时更新所有参数变化
- 支持切换不同图片预览效果

#### F6：批量导出
- 一键批量处理所有图片
- 显示处理进度
- 自动打包为 ZIP 下载
- 支持选择导出格式（JPG/PNG/WebP）
- 支持选择图片质量（JPG 压缩比）
- 保持原始文件名或自定义命名规则

#### F7：平台尺寸预设
- 小红书：3:4 竖图（1080×1440）、1:1 方图
- 淘宝：主图 800×800、详情页宽 750
- 拼多多：主图 800×800
- 自定义尺寸输入
- 自动裁剪/缩放适配

## 三、技术方案

### 3.1 技术栈选型

**方案 A：纯前端 Web 应用（当前采纳 MVP）**

| 层级 | 技术选型 | 理由 |
|-----|---------|------|
| 框架 | React 18 + TypeScript | 生态成熟，组件丰富 |
| 构建 | Vite | 启动快，开发体验好 |
| UI | Tailwind CSS v4（shadcn 风格） | 现代清爽，适合工具类 |
| 图片处理 | Canvas API | 客户端处理，无需后端，保护用户隐私 |
| 批量打包 | JSZip | 浏览器端打包 ZIP |
| 状态管理 | Zustand | 轻量，适合中小型应用 |
| PWA | vite-plugin-pwa | 可安装到手机桌面，移动端覆盖 |
| 部署 | Vercel / Netlify / GitHub Pages | 免费托管，自动部署 |

**核心优势：纯前端，图片不上传服务器，隐私安全，零服务器成本。**

**方案 B：全栈应用（后续扩展）**
- 后端：Node.js + Express / Next.js API Routes
- 存储：阿里云 OSS / 腾讯云 COS（临时存储）
- 队列：BullMQ（大批量异步处理）
- 适合：需要账号系统、云端模板保存的版本

### 3.2 核心技术难点与解决方案

#### 难点 1：大批量图片内存溢出
- **问题**：200 张高清图同时加载到内存，浏览器可能崩溃
- **方案**：分次处理（当前同步逐张处理）；后续用 OffscreenCanvas + Web Worker 提升性能

#### 难点 2：大图处理速度慢
- **问题**：单张 4K 图片 Canvas 处理耗时较长
- **方案**：后续引入 Web Worker 多线程处理；预览用降采样，导出用原图处理

#### 难点 3：中文字体加载
- **问题**：Canvas 绘制文字需要字体已加载，否则回退默认字体
- **方案**：`document.fonts.ready` 预加载 + Google Fonts (Noto Sans SC) + 系统字体栈回退

#### 难点 4：透明 PNG 水印合成
- **问题**：Logo 透明底与原图合成，alpha 通道处理
- **方案**：Canvas `globalCompositeOperation = 'source-over'`，直接绘制即可，浏览器原生支持

### 3.3 图片处理核心流程

```
用户上传图片
    ↓
读取为 Image / ImageBitmap 对象
    ↓
创建 Canvas，尺寸 = 原图尺寸（或平台预设）
    ↓
绘制原图到 Canvas
    ↓
根据水印参数绘制文字/图片水印
    ↓
导出为 Blob（JPG/PNG/WebP）
    ↓
加入 ZIP 打包队列
    ↓
全部处理完成 → 触发 ZIP 下载
```

## 四、页面结构与交互

### 4.1 页面结构

```
首页（落地页）
├── Hero 区：产品名 + Slogan + 立即使用按钮
├── 功能展示：6 个核心功能卡片
├── 使用流程：三步引导
├── 使用场景：小红书/电商/微商 场景展示
└── Footer：GitHub 链接、联系方式

工具页（核心应用）
├── 顶部导航：Logo + 功能切换 + GitHub Star
├── 左侧面板：图片列表（上传区 + 缩略图列表）
├── 中间区域：预览画布（原图/带水印切换）
├── 右侧面板：水印设置（文字/图片/位置/样式）
└── 底部操作栏：批量处理按钮 + 导出设置
```

### 4.2 核心交互流程

```
Step 1：用户进入工具页
Step 2：拖拽或点击上传图片（可批量）
Step 3：左侧显示图片缩略图列表，中间显示第一张预览
Step 4：右侧面板设置水印（选择文字/图片模式，输入内容，调整样式）
Step 5：中间预览实时更新
Step 6：调整水印位置（九宫格点击）
Step 7：点击"批量处理"
Step 8：显示处理进度条
Step 9：处理完成，自动下载 ZIP
Step 10：提示"处理完成，已下载 X 张图片"
```

### 4.3 关键交互细节

- **上传区**：拖拽时高亮边框，支持整个页面拖拽
- **图片列表**：支持点击切换预览，支持删除单张、清空全部
- **预览区**：支持原图/效果图切换
- **水印设置**：参数变化实时预览，无延迟感
- **处理中**：显示当前处理到第几张
- **错误处理**：某张图处理失败不影响其他，最后汇总报告失败列表
